kaleidoscope 앱 제작 지침
현재 작업의 데스크톱 쉘을 MCP 도구로 다룹니다. 개인 앱은 list_apps와 get_app으로 먼저 확인합니다. get_workspace로 현재 작업과 창을 확인합니다. workspace_id를 생략하면 MCP 연결의 작업을 사용합니다.
앱 정의 JSON의 필드는 id, name, description, requires, permissions, state, sources, assets, storage, agent, client, worker, opens, shortcuts, messages, locale, ui입니다. version은 서버가 부여하며 앱 정의에 넣지 않습니다. upload_app의 입력 스키마가 정확한 형식과 최신 블록 필드의 정본입니다. 모르는 필드는 넣지 않습니다.
requires.blocks는 사용하는 블록의 최소 지원 판이고 requires.modules는 사용하는 모듈별 판입니다. permissions에는 필요한 최소 권한만 선언합니다. 파일 경로는 사용자가 기기에서 고른 폴더 기준 상대 경로입니다. 다른 서비스의 주소나 데이터 모양은 앱 정의와 연결 설정에 두며 쉘 코드를 바꾸지 않습니다.
ui는 type으로 구분하는 블록 트리입니다. 배치는 split, stack, tabs, toolbar, section을 쓰고 데이터는 list, table, tree, feed, properties, metrics, chart, map, 입력은 input, select, slider, color, toggle, button, button_grid, 문서는 markdown, code, html_view, chat, 파일은 folder, explorer, 미디어는 image, media, 웹은 web_view와 sandbox를 사용합니다. code의 wrap을 생략하면 창 폭에서 줄바꿈하고 false면 줄바꿈하지 않습니다. 지원 블록과 모듈의 전체 목록은 도구 스키마를 확인합니다.
화면 맨 위에 metrics나 카드 줄로 지금 고른 것, 개수, 탭의 내용을 요약하지 않습니다. 아래 화면을 되풀이할 뿐이고 AI가 만든 페이지처럼 보입니다. metrics는 수치 자체가 앱의 본론일 때만 씁니다.
tree는 데이터 항목에 items를 사용하고, 폴더 파일에는 새 앱에서 folder를 사용합니다. tree.root와 file_tree는 기존 앱 정의 호환용 별칭이므로 새 정의에는 쓰지 않습니다. 데이터 tree는 by, selected, on_select를 받을 수 있습니다. folder는 blocks 13 이상이 필요하고 root를 파일 권한 {"permission":"docs"} 또는 storage 3판 이상이 필요한 문서 모음 {"entry":"documents"}으로 정합니다. 파일 뿌리는 folder 범위 권한이어야 하며 pc 권한은 explorer만 사용합니다. extensions, selected, on_select, read_only를 선택할 수 있습니다. markdown은 file, document, value 중 하나를 받습니다. file과 document는 기본으로 편집하고 read_only를 켜면 읽기 전용이며, value는 읽기 전용입니다. code는 file 또는 value 중 하나를 받습니다. file은 기본으로 편집하고 read_only를 켜면 읽기 전용이며, value는 읽기 전용입니다. language, follow, wrap을 선택할 수 있습니다. html_view는 document, file, value 중 하나를 받습니다. document는 storage 3판의 md 문서 모음을 사용하며 문서와 리비전 선택 상태를 씁니다. file과 value는 HTML을 읽기 전용으로 표시합니다. chat은 필드 없이 작업 대화를 열고 agent 모듈이 필요합니다. 로컬 에이전트 세션에는 permission, root, agents, selected, on_select를 모두 둡니다. button_grid는 columns, buttons, on_press를 받습니다.
html_view 문서 모음은 문서 이름/r1.html 같은 불변 리비전과 문서 이름/thread.json을 둡니다. thread.json의 comments에서 rev는 처음 단 리비전이고 anchor_rev는 앵커를 만든 리비전입니다. 앵커를 옮기면 anchor_rev를 바꾸고, 없는 값은 rev로 읽습니다. revisions에는 리비전 메타와 사용자가 고친 edits를 둡니다. thread.json은 읽은 revision으로 CAS해 쓰고 충돌하면 최신 값을 읽어 변경을 다시 적용합니다.
11판 sandbox는 asset, file, document, value 가운데 하나의 HTML을 격리된 프레임에서 실행합니다. 자산은 assets에 선언하고 html 형식으로 등록합니다. state_keys와 storage_entries에 적은 항목을 프레임의 window.kaleidoscope 브리지로 읽고 씁니다. slider와 color는 value 상태와 on_change 동작을 받고 input.rows는 여러 줄 입력의 높이를 정합니다.
12판 canvas는 client가 그리는 픽셀 표면이고 timeline은 초 단위 구간과 파형, 마커, 보조 눈금을 그립니다. client는 javascript 자산 entry와 inputs, outputs, actions, commands, state_keys, storage_entries를 선언하며 requires.modules.client를 1 이상으로 둡니다. 창마다 격리된 프레임에서 window.kaleidoscope를 사용합니다. publish로 내보낸 값은 {"client":"이름"}으로 블록에 바인딩하고 이벤트는 {"client":"동작"}으로 처리합니다. input, select, toggle, slider, color의 값과 list, table의 선택은 state 또는 client를 받습니다. client 입력과 코어 명령은 client 출력을 참조하지 않습니다.
기존 HTML을 화면째 실행할 때는 sandbox를 쓰고, 새 앱에서 로직과 화면을 나눌 때는 client와 빌딩 블록을 씁니다. 파일을 고르거나 저장하는 단추는 pick_files 또는 save_file 동작을 단독으로 지정합니다. 프레임은 files.read, files.write, files.close, files.abort로 선택한 파일과 저장 대상을 다룹니다. 재생 위치는 Clock 스냅샷으로 보내고 timeline이 그 사이를 보간합니다.
14판은 repeat, when, dialog, tour, anchor, progress와 기존 입력·텍스트·단추·배치·시간축의 새 필드를 선언합니다. repeat의 key는 항목의 유일한 키 필드이고 template의 값에서 {"item":"경로"}, 중첩 반복에서는 {"parent_item":"경로"}를 씁니다. 동작 값에는 쓰지 않고 $item이나 클라이언트 동작의 항목 context를 씁니다. 반복 안에서 $item은 현재 반복 항목이고 클라이언트 동작 context에는 item, parent_item, key, index가 담깁니다. button_grid는 단추 자체를 $item으로 쓰므로 repeat.template 안에는 둘 수 없습니다. 반복 안에는 button을 쓰세요. messages는 언어별 동일한 키의 문자열 사전이고 locale.state는 기본 언어가 든 상태 키입니다. 화면 값의 {"message":"키"}는 모든 언어에 있어야 합니다. 화면 전용 바인딩을 원천, client.inputs, commands에 쓰지 않습니다. shortcuts는 code, modifiers, action을 지정하며 같은 조합은 중복할 수 없습니다. 단축키의 primary는 기기의 Ctrl 또는 Cmd이고 수정 키가 정확히 일치해야 합니다. 입력 중과 다른 창이 앞에 있을 때는 실행하지 않습니다. client 2의 onLifecycle은 visible, focused, viewport(width, height, coarse_pointer)와 phase(ready, change, closing)를 전달합니다. 숨겨지면 앱이 불필요한 화면 갱신을 멈추고 내보내기는 계속합니다. 새 client 기능은 client 2, 공개 바이트 읽기는 http 2를 요구합니다.
client.http_permissions에 선언한 http 권한은 window.kaleidoscope.http.read({permission,path,query})로 읽고 {bytes:ArrayBuffer,mime}을 받습니다. 공개 HTTPS 호스트와 허용 경로만 읽고 사설 주소와 리다이렉트는 거부하며 응답은 16MiB까지입니다. client.device_storage.prefixes에 허용할 접두어를 선언하면 blobs.put({key,file_id}) 또는 blobs.put({key,bytes})로 기기에 보관하고 blobs.open({key})의 파일 핸들을 files.read로 읽습니다. blobs.list({prefix})와 blobs.remove({key})도 제공합니다. 파일은 512MiB까지이며 서버와 앱별로 분리되고 다른 기기에 동기화되지 않습니다.
값은 리터럴, 상태 참조 {"state":"키"}, 식 {"expr":"JSONata 식"}이며 UI 값에는 클라이언트 출력 참조도 쓸 수 있습니다. 식에서 $state, $data, $storage, $data_meta를 읽고 동작에서는 $event, $item, $modifiers를 읽습니다. $modifiers는 shift, alt, ctrl, meta 참거짓이며 입력되지 않은 경우 모두 false입니다. sources는 파일, 폴더, 연결 요청 또는 공개 HTTPS 원천을 선언합니다. 블록 이벤트에 set_state, refresh, call, set_storage 같은 동작을 연결합니다. actions라는 최상위 필드는 없습니다.
원천을 넣기 전에 호출 수를 셉니다. 호스트마다 기본 화면의 분당 호출이 6회를 넘지 않게 합니다. upload_app과 preview_app이 넘은 호스트를 warnings로 알립니다. refresh_secs는 자료가 실제로 바뀌는 주기보다 짧게 두지 않고, 일간이나 연간 자료에는 두지 않습니다. 코인이나 도시처럼 항목마다 부르는 원천은 묶음 요청을 먼저 찾습니다. 시세처럼 자주 바뀌는 값을 다른 원천의 쿼리에 넣지 않습니다. 값이 바뀔 때마다 그 원천을 다시 부르기 때문입니다. 코어는 보이지 않는 창, 안 보는 탭, 접힌 섹션에서만 쓰는 원천을 부르지 않고, 다시 보일 때 기한이 지난 것만 받습니다. 429와 Retry-After는 호스트 단위로 지키며 마지막 값을 유지합니다. 탭 안에서만 쓰는 값은 그 탭의 블록만 읽습니다. 다른 블록이 읽거나 식이 $data 전체를 읽으면 그 원천은 쉬지 못합니다. 워커가 외부를 부를 때는 429를 받으면 그 주기를 끝내고 Retry-After까지 부르지 않습니다.
권한 id에는 소문자, 숫자와 하이픈을 쓰며 profiler 권한은 밑줄도 쓸 수 있습니다. profiler 모듈 1판의 권한 {"module":"profiler","id":"이름","label":"설명"}은 이 기기 코어의 성능 통계를 제공합니다. request 원천으로 GET /snapshot을 읽고 call로 POST /clear 또는 POST /benchmark를 실행합니다. 서버 미리 보기에서는 data 표본이 필요합니다.
storage.entries는 JSON 또는 Markdown 항목의 키, 스키마, 기본값을 선언합니다. 문서 모음은 collection:true인 숨김 Markdown 항목이며 기본값은 빈 문자열이고 key 아래에 문서별 행을 둡니다. 모음 문서는 list_app_storage(entry_id), read_app_storage(entry_id, doc), write_app_storage(entry_id, doc), reset_app_storage(entry_id, doc), move_app_storage로 다룹니다. 각 문서는 1MiB 한도와 revision CAS를 따릅니다. 작업별 키에는 {workspace_id}를 씁니다. 고정 항목에는 doc을 쓰지 않습니다. worker는 앱의 서버 실행과 주기 작업을 선언하며 시크릿 값은 앱 정의에 넣지 않습니다. opens는 파일 확장자, 폴더 권한과 경로 상태 키를 선언합니다.

파일 권한은 files 1판에서 폴더 안 항목을 나열하고 읽고 씁니다. files 2판의 pc 범위는 읽기 전용입니다. files 3판은 readwrite + folder 권한에서 폴더 생성, 이름 변경, 이동, 복사와 삭제를 할 수 있습니다. 삭제는 기본적으로 시스템 휴지통을 사용하며, 휴지통을 사용할 수 없으면 오류로 끝납니다. 영구 삭제는 별도 요청입니다. 이름이 겹치면 덮어쓰지 않으며 복사만 자동으로 「- 복사본」 이름을 붙입니다. files.reveal과 files.path는 읽기 권한으로 쓸 수 있습니다.
worker.webhook은 외부 POST 트리거를 선언합니다. enabled_entry는 기본값이 false인 전역 불리언 저장 항목이며, token_secret을 지정하면 미리 시크릿을 설정해야 호출할 수 있습니다. 응답을 http_response로 정하고 defer로 선언된 동작을 뒤에 실행할 수 있습니다. worker.calls에 다른 앱 id를 선언하면 파이썬에서 kaleidoscope_worker.call_app과 read_app_storage를 사용할 수 있습니다. 자기 호출, 순환 호출과 네 단계 초과 호출은 거부됩니다.
preview_app으로 실제 상태와 표본 데이터의 식을 먼저 계산합니다. 기기 전용 원천은 표본 data를 제공합니다. upload_app으로 정의를 등록하고 open_app으로 현재 작업에 띄운 뒤 get_workspace로 결과를 확인합니다. 기본 앱은 upload_app으로 수정하거나 삭제할 수 없습니다. 시험용 앱은 확인 뒤 정리합니다.
