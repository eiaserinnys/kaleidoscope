kaleidoscope 앱 제작 지침
kaleidoscope는 에이전트가 앱을 만들어 올리면 사용자가 창으로 띄워 쓰는 데스크톱 쉘입니다. 사용자가 앱을 만들거나 고쳐 달라고 하면 이 지침을 따릅니다. 앞부분은 앱의 구성과 할 수 있는 일의 경계이고, 뒷부분은 필드와 블록 참조입니다. 정확한 형식의 정본은 upload_app의 입력 스키마입니다.

앱이란
앱은 JSON 앱 정의 하나입니다. upload_app으로 서버의 레지스트리에 올리면 사용자의 쉘이 받아 창으로 띄우며, 쉘을 다시 빌드하지 않습니다. 화면은 쉘에 든 블록을 ui 트리로 엮어 그립니다. 값은 코어가 창 상태, 앱 저장소, 원천(파일, 폴더, HTTP)을 JSONata 식으로 읽어 계산하고, 블록의 이벤트에는 동작을 연결합니다.

갈래 고르기
- 블록만: 목록, 표, 입력 폼, 문서, 대시보드처럼 자료를 보여 주고 고치는 앱의 기본입니다. 로딩과 오류, 로그인 표시는 블록이 스스로 합니다. 여기서 시작하고 모자랄 때만 아래로 갑니다.
- client와 canvas: 게임, 그림판, 실시간 시각화처럼 프레임마다 그리거나 입력에 바로 반응해야 할 때 씁니다. JavaScript 자산이 창마다 격리된 프레임에서 돌며 canvas에 그리고, 값을 내보내 다른 블록이 쓰게 합니다.
- sandbox: 이미 있는 HTML을 화면째 띄울 때 씁니다.
- worker: 서버에서 도는 Python 코드입니다. 주기 실행, 웹훅, 시크릿이 필요한 호출, 앱 사이 호출에 씁니다. 실행 한 번은 60초까지입니다. 쉘이 내 PC 서버에 연결돼 있으면 그 PC에서, 원격 서버에 연결돼 있으면 그 서버에서 돕니다.
한 앱에서 섞어도 됩니다.

할 수 있는 것
- 앱을 올리고, 고치고, 지우고, 띄웁니다(upload_app, open_app, delete_app). 같은 id로 올리면 새 판이 되고 열린 창이 새 판으로 옮겨 갑니다.
- 사용자가 창에서 고른 폴더의 파일을 읽고 씁니다(files 권한).
- 공개 HTTPS를 읽습니다(http 권한). 로그인이나 비밀 헤더가 필요한 서비스는 서버에 연결로 등록해 부릅니다(set_connection, connection 권한).
- 계정과 앱마다 설정과 문서를 남깁니다(storage, 항목이나 문서 하나에 1MiB까지). 기기에만 남길 큰 파일은 client의 blobs를 씁니다.
- 이미지, HTML, 스크립트 같은 불변 자산을 올려 씁니다(upload_asset).
- 웹 페이지를 창에 띄웁니다(web_view).

할 수 없는 것
- 쉘, 블록, 코어의 코드를 고치지 못합니다. 없는 블록이나 스키마에 없는 필드는 올릴 때 거부됩니다. 원하는 화면이 블록에 없으면 canvas나 sandbox로 그릴 수 있는지 보고, 그래도 안 되면 무엇이 안 되는지 사용자에게 말합니다.
- 블록의 모양은 쉘의 테마를 따르고 임의 CSS를 넣지 못합니다. 앱이 정하는 것은 스키마에 있는 값(분할 비율, 간격 단계, 항목과 배지 색)뿐입니다. 모양을 직접 정해야 하면 canvas나 sandbox를 씁니다.
- 기본 앱은 고치거나 지우지 못하고 get_app으로 정의를 읽지도 못합니다. 기본 앱의 저장소 값은 write_app_storage로 바꿀 수 있습니다. 다르게 동작해야 하면 다른 id의 새 앱으로 만듭니다.
- 앱은 허락받지 않은 파일에 닿지 못합니다. 폴더 범위 권한은 사용자가 창마다, 기기마다 그 창에서 고른 폴더 안만 읽고 씁니다. PC 범위 권한(scope pc)은 기기에서 앱과 권한마다 처음 한 번 허용을 받은 뒤 explorer에서 읽기만 합니다. 어느 쪽이든 에이전트의 작업 폴더와 별개이고 worker에 전달되지 않습니다.
- 프레임 안의 코드(client, sandbox)는 바깥 네트워크에 직접 나가지 못합니다. fetch, WebSocket, 외부 스크립트와 이미지가 막혀 있습니다. 바깥 자료는 원천이나 http.read로 읽습니다. 공개 HTTPS는 앱이 선언한 경로만 읽고 사설 주소와 리다이렉트는 거부됩니다.
- 시크릿 값을 앱 정의에 넣지 못합니다. worker 시크릿은 set_app_secret, 연결 헤더는 set_connection으로 넣습니다.
- 사용자 대신 폴더를 고르거나 로그인하지 못합니다. 그 차례가 오면 사용자에게 무엇을 눌러야 하는지 알립니다.

확인 순서
1. 고치는 앱이면 list_apps와 get_app으로 지금 판을 받습니다.
2. preview_app으로 식이 내는 값과 warnings를 봅니다. 화면을 그리지는 않습니다. 기기 원천은 data로 표본을 줍니다.
3. upload_app으로 올립니다. 기본으로 창도 띄우며, 이미 올린 앱을 다시 띄울 때는 open_app을 씁니다. 응답의 open_sent_to는 띄우기를 요청한 기기 수입니다. 0이면 창이 뜨지 않으니 note가 있으면 읽고 사용자에게 알립니다.
4. get_workspace로 창이 떴는지 봅니다. 창마다 상태, 고른 폴더, data_errors가 나옵니다.
5. 실제 화면은 사용자에게 확인받습니다. 위 도구로는 그려진 화면을 볼 수 없고, client 코드가 도는지와 키가 먹는지도 알 수 없습니다. 보지 못한 것은 못 봤다고 말하고, 무엇을 해 보면 되는지 짧게 알립니다.
6. 화면을 봐야 판단할 수 있으면 사용자에게 그 창 제목 줄의 같이 보기를 켜 달라고 합니다. 켜면 사용자가 다음 말을 보낼 때 그 창에 보이는 글이 함께 오고, canvas, 이미지, 영상, 웹 화면이 보이는 창은 지금 보는 데스크톱에 있을 때 창 그림이 첨부됩니다. 보이는 글 전체는 get_shared_view로 읽습니다.
7. 시험용 앱은 확인 뒤 지웁니다.

앱을 올릴 수 없는 세션
도구 목록에 upload_app이 없으면 앱을 올릴 수 없습니다. 쉘이 서버에 연결되어 있지 않거나 이 에이전트가 HTTP MCP를 쓰지 못하는 경우입니다. 만들었다고 말하지 말고 그 사실을 사용자에게 알립니다.

참조
도구의 workspace_id를 빼면 이 MCP 연결의 작업을 씁니다.
앱 정의 JSON의 필드는 id, name, description, requires, permissions, state, state_migrate, sources, assets, storage, agent, client, worker, opens, shortcuts, messages, locale, ui입니다. version은 서버가 부여하며 앱 정의에 넣지 않습니다. upload_app의 입력 스키마가 정확한 형식과 최신 블록 필드의 정본입니다. 모르는 필드는 넣지 않습니다. state_migrate는 앱 판을 올릴 때 옛 상태에 없는 키의 값만 JSONata 식으로 계산하며 새 창에는 적용하지 않습니다. opens.set_state는 탐색기에서 파일을 열 때 경로와 함께 창 상태에 쓸 값을 선언합니다.
requires.blocks는 사용하는 블록의 최소 지원 판이고 requires.modules는 사용하는 모듈별 판입니다. permissions에는 필요한 최소 권한만 선언합니다. 파일 경로는 사용자가 기기에서 고른 폴더 기준 상대 경로입니다. 다른 서비스의 주소나 데이터 모양은 앱 정의와 연결 설정에 두며 쉘 코드를 바꾸지 않습니다.
ui는 type으로 구분하는 블록 트리입니다. 배치는 split, stack, tabs, toolbar, section을 쓰고 데이터는 list, table, tree, feed, properties, metrics, chart, map, 입력은 input, select, slider, color, toggle, button, button_grid, 문서는 markdown, code, html_view, chat, 파일은 folder, explorer, 미디어는 image, media, 웹은 web_view와 sandbox를 사용합니다. tabs.header:false는 탭 줄 없이 선택된 탭 내용만 보이고 tabs.keep_mounted:true는 방문한 탭을 숨겨 유지합니다. tabs.collapsible:true는 분할 칸의 접기를 탭 줄에서 맡으며 header:false와 함께 쓸 수 없습니다. 이 필드들, state_migrate, opens.set_state 가운데 하나를 쓰면 requires.blocks는 15 이상이어야 합니다. 16판부터 tabs[].label, toggle.label, slider.label, color.label, input.label과 input.placeholder, select.label과 select.placeholder, dialog.close_label과 dialog.cancel_label, tour.labels.previous·next·done·skip에 state, expr, client, message, item, parent_item 바인딩을 쓸 수 있습니다. 평문 문자열은 그대로 직렬화되므로 16판을 요구하지 않습니다. code의 wrap을 생략하면 창 폭에서 줄바꿈하고 false면 줄바꿈하지 않습니다. 지원 블록과 모듈의 전체 목록은 도구 스키마를 확인합니다.
화면 맨 위에 metrics나 카드 줄로 지금 고른 것, 개수, 탭의 내용을 요약하지 않습니다. 아래 화면을 되풀이할 뿐이고 AI가 만든 페이지처럼 보입니다. metrics는 수치 자체가 앱의 본론일 때만 씁니다.
tree는 데이터 항목에 items를 사용하고, 폴더 파일에는 새 앱에서 folder를 사용합니다. tree.root와 file_tree는 기존 앱 정의 호환용 별칭이므로 새 정의에는 쓰지 않습니다. 데이터 tree는 by, selected, on_select를 받을 수 있습니다. folder는 blocks 13 이상이 필요하고 root를 파일 권한 {"permission":"docs"} 또는 storage 3판 이상이 필요한 문서 모음 {"entry":"documents"}으로 정합니다. 파일 뿌리는 folder 범위 권한이어야 하며 pc 권한은 explorer만 사용합니다. extensions, selected, on_select, read_only를 선택할 수 있고 15판 header:false는 머리 줄을 숨깁니다. markdown은 file, document, value 중 하나를 받습니다. file과 document는 기본으로 편집하고 read_only를 켜면 읽기 전용이며, value는 읽기 전용입니다. code는 file 또는 value 중 하나를 받습니다. file은 기본으로 편집하고 read_only를 켜면 읽기 전용이며, value는 읽기 전용입니다. language, follow, wrap을 선택할 수 있습니다. html_view는 document, file, value 중 하나를 받습니다. document는 storage 3판의 md 문서 모음을 사용하며 문서와 리비전 선택 상태를 씁니다. file과 value는 HTML을 읽기 전용으로 표시합니다. chat은 필드 없이 작업 대화를 열고 agent 모듈이 필요합니다. 로컬 에이전트 세션에는 permission, root, agents, selected, on_select를 모두 둡니다. button_grid는 columns, buttons, on_press를 받습니다.
html_view 문서 모음은 문서 이름/r1.html 같은 불변 리비전과 문서 이름/thread.json을 둡니다. thread.json의 comments에서 rev는 처음 단 리비전이고 anchor_rev는 앵커를 만든 리비전입니다. 앵커를 옮기면 anchor_rev를 바꾸고, 없는 값은 rev로 읽습니다. revisions에는 리비전 메타와 사용자가 고친 edits를 둡니다. thread.json은 읽은 revision으로 CAS해 쓰고 충돌하면 최신 값을 읽어 변경을 다시 적용합니다.
11판 sandbox는 asset, file, document, value 가운데 하나의 HTML을 격리된 프레임에서 실행합니다. 자산은 assets에 선언하고 html 형식으로 등록합니다. state_keys와 storage_entries에 적은 항목을 프레임의 window.kaleidoscope 브리지로 읽고 씁니다. slider와 color는 value 상태와 on_change 동작을 받고 input.rows는 여러 줄 입력의 높이를 정합니다.
12판 canvas는 client가 그리는 픽셀 표면이고 timeline은 초 단위 구간과 파형, 마커, 보조 눈금을 그립니다. client는 javascript 자산 entry와 inputs, outputs, actions, commands, state_keys, storage_entries를 선언하며 requires.modules.client를 1 이상으로 둡니다. 창마다 격리된 프레임에서 window.kaleidoscope를 사용합니다. publish로 내보낸 값은 {"client":"이름"}으로 블록에 바인딩하고 이벤트는 {"client":"동작"}으로 처리합니다. input, select, toggle, slider, color의 값과 list, table의 선택은 state 또는 client를 받습니다. client 입력과 코어 명령은 client 출력을 참조하지 않습니다.
14판 canvas.surface는 문자열 바인딩입니다. repeat 안에서는 {"item":"surface"}처럼 각 항목의 서로 다른 이름을 씁니다. client.surfaces.on(id, listener)는 표면이 붙으면 canvas, cssWidth, cssHeight, dpr, visible, resize를, 떨어지면 null을 전달합니다. 크기나 visible이 바뀌면 resize의 resize 이벤트가 납니다. visible이 false이면 해당 표면의 그리기 루프를 멈추고 true이면 다시 시작하세요. 다시 붙은 표면은 이전 표면과 별개입니다.
기존 HTML을 화면째 실행할 때는 sandbox를 쓰고, 새 앱에서 로직과 화면을 나눌 때는 client와 빌딩 블록을 씁니다. 파일을 고르거나 저장하는 단추는 pick_files 또는 save_file 동작을 단독으로 지정합니다. 프레임은 files.read, files.write, files.truncate, files.close, files.abort로 선택한 파일과 저장 대상을 다룹니다. files.truncate(sink, size)는 현재 창이 연 출력 대상의 길이를 바꿉니다. 재생 위치는 Clock 스냅샷으로 보내고 timeline이 그 사이를 보간합니다.
client 2의 files.save_prompt({suggested_name,mime})는 선언한 client 동작 안에서 저장 대화상자를 열고 file_id 또는 null을 돌려줍니다. file_id에 files.write, files.close, files.abort를 사용합니다. 브라우저에서는 기존 save_file 저장 경로를 씁니다. client.capabilities에 share 또는 keep_awake를 선언한 앱만 window.kaleidoscope.host API를 씁니다. host.can_share(file_id)는 지원 여부를 boolean으로, host.share(file_id,title)는 {status:"shared"|"cancelled"|"failed"}를 돌려줍니다. host.keep_awake(enabled)는 성공 여부를 boolean으로 돌려주며 화면이 숨겨지거나 창이 닫히면 화면 켜짐 유지를 해제합니다. host API는 선언한 client 동작 안에서 호출합니다. capabilities를 쓰려면 requires.blocks 14 이상, requires.modules.client 2 이상이 필요합니다.
14판은 repeat, when, dialog, tour, anchor, progress와 기존 입력·텍스트·단추·배치·시간축의 새 필드를 선언합니다. repeat의 key는 항목의 유일한 키 필드이고 template의 값에서 {"item":"경로"}, 중첩 반복에서는 {"parent_item":"경로"}를 씁니다. 동작 값에는 쓰지 않고 $item이나 클라이언트 동작의 항목 context를 씁니다. 반복 안에서 $item은 현재 반복 항목이고 클라이언트 동작 context에는 item, parent_item, key, index가 담깁니다. button_grid는 단추 자체를 $item으로 쓰므로 repeat.template 안에는 둘 수 없습니다. 반복 안에는 button을 쓰세요. messages는 언어별 동일한 키의 문자열 사전이고 locale.state는 기본 언어가 든 상태 키입니다. 화면 값의 {"message":"키"}는 모든 언어에 있어야 합니다. 화면 전용 바인딩을 원천, client.inputs, commands에 쓰지 않습니다. shortcuts는 code, modifiers, action을 지정하며 같은 조합은 중복할 수 없습니다. 단축키의 primary는 기기의 Ctrl 또는 Cmd이고 수정 키가 정확히 일치해야 합니다. 입력 중과 다른 창이 앞에 있을 때는 실행하지 않습니다. client 2의 onLifecycle은 visible, focused, viewport(width, height, coarse_pointer)와 phase(ready, change, closing)를 전달합니다. 숨겨지면 앱이 불필요한 화면 갱신을 멈추고 내보내기는 계속합니다. 새 client 기능은 client 2, 공개 바이트 읽기는 http 2를 요구합니다. 같은 canvas 표면 이름과 anchor id는 서로 다른 when 분기에 둘 수 있으며, 두 분기가 동시에 참이면 나중에 마운트된 쪽이 해당 표면을 갖습니다.
