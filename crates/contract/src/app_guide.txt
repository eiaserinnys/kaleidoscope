kaleidoscope 앱 제작 지침
kaleidoscope는 에이전트가 앱을 만들어 올리면 사용자가 창으로 띄워 쓰는 데스크톱 쉘입니다. 사용자가 앱을 만들거나 고쳐 달라고 하면 이 지침을 따릅니다. 앞부분은 앱의 구성과 할 수 있는 일의 경계이고, 뒷부분은 필드와 블록 참조입니다. 정확한 형식의 정본은 upload_app의 입력 스키마입니다.

앱이란
앱은 JSON 앱 정의 하나입니다. upload_app으로 서버의 레지스트리에 올리면 사용자의 쉘이 받아 창으로 띄우며, 쉘을 다시 빌드하지 않습니다. 화면은 쉘에 든 블록을 ui 트리로 엮어 그립니다. 값은 코어가 창 상태, 앱 저장소, 원천(파일, 폴더, HTTP)을 JSONata 식으로 읽어 계산하고, 블록의 이벤트에는 동작을 연결합니다.

갈래 고르기
- 블록만: 목록, 표, 입력 폼, 문서, 대시보드처럼 자료를 보여 주고 고치는 앱의 기본입니다. 로딩과 오류, 로그인 표시는 블록이 스스로 합니다. 여기서 시작하고 모자랄 때만 아래로 갑니다.
- client와 canvas: 게임, 그림판, 실시간 시각화처럼 프레임마다 그리거나 입력에 바로 반응해야 할 때 씁니다. JavaScript 자산이 창마다 격리된 프레임에서 돌며 canvas에 그리고, 값을 내보내 다른 블록이 쓰게 합니다.
- sandbox: 이미 있는 HTML을 화면째 띄울 때 씁니다.
- worker: 서버에서 도는 Python 코드입니다. 주기 실행, 웹훅, 시크릿이 필요한 호출, 앱 사이 호출에 씁니다. 실행 한 번은 60초까지입니다. 쉘이 내 PC 서버에 연결돼 있으면 그 PC에서, 원격 서버에 연결돼 있으면 그 서버에서 돕니다.
한 앱에서 섞어도 됩니다.

할 수 있는 것
- 앱을 올리고, 고치고, 지우고, 띄웁니다(upload_app, open_app, delete_app). 같은 id로 올리면 새 판이 되고 열린 창이 새 판으로 옮겨 갑니다.
- 사용자가 창에서 고른 폴더의 파일을 읽고 씁니다(files 권한).
- 사용자가 허용한 이 PC의 프로그램을 실행합니다(process 권한).
- 허용한 프로그램은 사용자 OS 계정의 파일과 네트워크 권한으로 실행됩니다. 파일 접근을 설명할 때 블록과 client의 폴더 제한과 프로그램의 OS 권한을 구분합니다.
- 공개 HTTPS를 읽습니다(http 권한). 로그인이나 비밀 헤더가 필요한 서비스는 서버에 연결로 등록해 부릅니다(set_connection, connection 권한).
- 계정과 앱마다 설정과 문서를 남깁니다(storage, 항목이나 문서 하나에 1MiB까지). 기기에만 남길 큰 파일은 client의 blobs를 씁니다.
- 이미지, HTML, 스크립트 같은 불변 자산을 올려 씁니다(upload_asset).
- 웹 페이지를 창에 띄웁니다(web_view).

할 수 없는 것
- 쉘, 블록, 코어의 코드를 고치지 못합니다. 없는 블록이나 스키마에 없는 필드는 올릴 때 거부됩니다. 원하는 화면이 블록에 없으면 canvas나 sandbox로 그릴 수 있는지 보고, 그래도 안 되면 무엇이 안 되는지 사용자에게 말합니다.
- 블록의 모양은 쉘의 테마를 따르고 임의 CSS를 넣지 못합니다. 앱이 정하는 것은 스키마에 있는 값(분할 비율, 간격 단계, 항목과 배지 색)뿐입니다. 모양을 직접 정해야 하면 canvas나 sandbox를 씁니다.
- 기본 앱은 고치거나 지우지 못하고 get_app으로 정의를 읽지도 못합니다. 기본 앱의 저장소 값은 write_app_storage로 바꿀 수 있습니다. 다르게 동작해야 하면 다른 id의 새 앱으로 만듭니다.
- 블록과 client는 허락받지 않은 파일에 닿지 못합니다. 폴더 범위 권한은 사용자가 창마다, 기기마다 그 창에서 고른 폴더 안만 읽고 씁니다. PC 범위 권한(scope pc)은 기기에서 앱과 권한마다 처음 한 번 허용을 받은 뒤 explorer에서 읽기만 합니다. 어느 쪽이든 에이전트의 작업 폴더와 별개이고 worker에 전달되지 않습니다. 사용자가 실행을 허용한 프로그램은 일반 프로그램처럼 사용자 계정의 파일 권한을 가집니다.
- 프레임 안의 코드(client, sandbox)는 바깥 네트워크에 직접 나가지 못합니다. fetch, WebSocket, 외부 스크립트와 이미지가 막혀 있습니다. 바깥 자료는 원천이나 http.read로 읽습니다. 공개 HTTPS는 앱이 선언한 경로만 읽고 사설 주소와 리다이렉트는 거부됩니다.
- 시크릿 값을 앱 정의에 넣지 못합니다. worker 시크릿은 set_app_secret, 연결 헤더는 set_connection으로 넣습니다.
- 사용자 대신 폴더를 고르거나 로그인하지 못합니다. 그 차례가 오면 사용자에게 무엇을 눌러야 하는지 알립니다.

확인 순서
1. 고치는 앱이면 list_apps와 get_app으로 지금 판을 받습니다.
2. preview_app으로 식이 내는 값과 warnings를 봅니다. 화면을 그리지는 않습니다. 기기 원천은 data로 표본을 줍니다.
3. upload_app으로 올립니다. 기본으로 창도 띄우며, 이미 올린 앱을 다시 띄울 때는 open_app을 씁니다. 작업을 지정하면 그 작업을 지금 띄운 동기화 기기로 가며, 기기 MCP 연결은 그 기기로 갑니다. 응답의 open_sent_to는 띄우기를 요청한 기기 수입니다. 0이면 창이 뜨지 않으니 note가 있으면 읽고 사용자에게 알립니다.
4. get_workspace로 창이 떴는지 봅니다. 창마다 상태, 고른 폴더, data_errors가 나옵니다.
5. 사용자에게 창의 같이 보기를 켜 달라고 합니다. get_shared_view로 window_id를 찾고 read_window(window_id)로 view_id와 [번호]를 읽습니다. act_window(window_id, view_id, action)의 click, type, select, key, scroll로 조작하고 새 view_id와 mode(diff, full, unchanged)로 결과를 확인합니다. 다음 동작에는 새 view_id를 씁니다.
6. 시각 확인이나 canvas·격리 프레임(sandbox, html_view)의 point에만 image: true로 그림과 geometry(css_width, css_height, pixel_width, pixel_height)를 받습니다. point는 그림의 픽셀 좌표입니다. settled: false나 applied: true 오류 뒤에는 다시 읽습니다. 같이 보기가 꺼진 창과 파일·실행 허용 화면은 사용자에게 조작을 요청합니다.
7. 시험용 앱은 확인 뒤 지웁니다.

앱을 올릴 수 없는 세션
도구 목록에 upload_app이 없으면 앱을 올릴 수 없습니다. 쉘이 서버에 연결되어 있지 않거나 이 에이전트가 HTTP MCP를 쓰지 못하는 경우입니다. 만들었다고 말하지 말고 그 사실을 사용자에게 알립니다.

참조
도구의 workspace_id를 빼면 이 MCP 연결의 작업을 씁니다.
앱 정의 JSON의 필드는 id, name, description, icon, requires, permissions, state, state_migrate, sources, assets, storage, agent, client, worker, opens, shortcuts, messages, locale, ui입니다. version은 서버가 부여하며 앱 정의에 넣지 않습니다. upload_app의 입력 스키마가 정확한 형식과 최신 블록 필드의 정본입니다. 모르는 필드는 넣지 않습니다. state_migrate는 앱 판을 올릴 때 옛 상태에 없는 키의 값만 JSONata 식으로 계산하며 새 창에는 적용하지 않습니다. opens.set_state는 탐색기에서 파일을 열 때 경로와 함께 창 상태에 쓸 값을 선언합니다.
앱 아이콘은 icon: {"asset":"자산-id", "version":1}로 지정합니다. 같은 id와 판을 assets: [{"id":"자산-id", "version":1}]에 선언하고 requires.modules.assets를 1 이상, requires.blocks를 26 이상으로 둡니다. 자산 형식은 SVG, PNG, WebP이며 단색 선 SVG(viewBox 24칸, 선 두께 1.5px, currentColor)를 권장하지만 강제하지 않습니다.
requires.blocks는 사용하는 블록의 최소 지원 판이고 requires.modules는 사용하는 모듈별 판입니다. permissions에는 필요한 최소 권한만 선언합니다. 파일 경로는 사용자가 기기에서 고른 폴더 기준 상대 경로입니다. 다른 서비스의 주소나 데이터 모양은 앱 정의와 연결 설정에 두며 쉘 코드를 바꾸지 않습니다.
19판에서는 repeat.template 안의 값 바인딩에서 `{"message":{"item":"label_key"}}`로 현재 자료 항목의 문자열 키를 메시지로 바꿀 수 있습니다. 경로는 `{ "item": "label_key" }`와 같은 현재 항목 범위를 따르며, 현재 언어에 번역이 없으면 기본 언어를 찾습니다. 기존 `{"message":"ready"}` 고정 키 형식은 그대로 씁니다.
27판의 split.column_below는 row split 자신의 폭이 지정한 양수 CSS px보다 작을 때 칸을 위아래로 쌓아 스크롤합니다. 쌓인 동안 sizes 비율과 크기 조절 손잡이를 쓰지 않으며, 다시 넓어지면 sizes 초기값을 사용합니다. repeat.gap은 none, small, medium, large로 항목 간격을 지정하며 생략하면 기존 간격을 유지합니다. 두 필드를 쓰면 requires.blocks는 27 이상이어야 합니다.
ui는 type으로 구분하는 블록 트리입니다. 배치는 split, stack, tabs, toolbar, section을 쓰고 데이터는 list, table, tree, feed, properties, metrics, chart, map, 입력은 input, select, slider, color, toggle, button, button_grid, 문서는 markdown, code, html_view, chat, 파일은 folder, explorer, 미디어는 image, media, 웹은 web_view와 sandbox를 사용합니다. toolbar 높이는 쉘이 한 값으로 고정하고 조작을 한 줄에 놓으며 좁으면 가로로 스크롤합니다. 여러 줄 입력이나 이름표가 달린 입력은 toolbar 밖 아래 양식에 놓습니다. tabs.header:false는 탭 줄 없이 선택된 탭 내용만 보이고 tabs.keep_mounted:true는 방문한 탭을 숨겨 유지합니다. tabs.collapsible:true는 분할 칸의 접기를 탭 줄에서 맡으며 header:false와 함께 쓸 수 없습니다. 이 필드들, state_migrate, opens.set_state 가운데 하나를 쓰면 requires.blocks는 15 이상이어야 합니다. 16판부터 tabs[].label, toggle.label, slider.label, color.label, input.label과 input.placeholder, select.label과 select.placeholder, dialog.close_label과 dialog.cancel_label, tour.labels.previous·next·done·skip에 state, expr, client, message, item, parent_item 바인딩을 쓸 수 있습니다. 평문 문자열은 그대로 직렬화되므로 16판을 요구하지 않습니다. stack.align, dialog.on_confirm, dialog.danger, input.columns, button.preview, button.prefix, 동적 PropertyField.label, format swatches, properties.layout, canvas.loading, when.min_width 또는 when.max_width를 쓰면 requires.blocks는 19 이상이어야 합니다. code의 wrap을 생략하면 창 폭에서 줄바꿈하고 false면 줄바꿈하지 않습니다. 지원 블록과 모듈의 전체 목록은 도구 스키마를 확인합니다.
화면 맨 위에 metrics나 카드 줄로 지금 고른 것, 개수, 탭의 내용을 요약하지 않습니다. 아래 화면을 되풀이할 뿐이고 AI가 만든 페이지처럼 보입니다. metrics는 수치 자체가 앱의 본론일 때만 씁니다.
tree는 데이터 항목에 items를 사용하고, 폴더 파일에는 새 앱에서 folder를 사용합니다. tree.root와 file_tree는 기존 앱 정의 호환용 별칭이므로 새 정의에는 쓰지 않습니다. 데이터 tree는 by, selected, on_select를 받을 수 있습니다. folder는 blocks 13 이상이 필요하고 root를 파일 권한 {"permission":"docs"} 또는 storage 3판 이상이 필요한 문서 모음 {"entry":"documents"}으로 정합니다. 파일 뿌리는 folder 범위 권한이어야 하며 pc 권한은 explorer만 사용합니다. extensions, selected, on_select, read_only를 선택할 수 있고 15판 header:false는 머리 줄을 숨깁니다. markdown은 file, document, value 중 하나를 받습니다. file과 document는 기본으로 편집하고 read_only를 켜면 읽기 전용이며, value는 읽기 전용입니다. code는 file 또는 value 중 하나를 받습니다. file은 기본으로 편집하고 read_only를 켜면 읽기 전용이며, value는 읽기 전용입니다. language, follow, wrap을 선택할 수 있습니다. html_view는 document, file, value 중 하나를 받습니다. document는 storage 3판의 md 문서 모음을 사용하며 문서와 리비전 선택 상태를 씁니다. file과 value는 HTML을 읽기 전용으로 표시합니다. chat은 필드 없이 작업 대화를 열고 agent 모듈이 필요합니다. button_grid는 columns, buttons, on_press를 받습니다.
list, table, 데이터 tree, feed의 item_menu는 blocks 20 이상에서 {label, on_select, danger?, confirm?} 항목 배열을 받습니다. on_select의 $event와 $item은 그 블록의 항목 선택과 같고 copy_text는 {"item":"필드"}로 항목 값을 가리킵니다. confirm.body도 {"item":"필드"}로 대상을 보일 수 있습니다.
blocks 30부터 list.on_remove는 항목마다 빼기 단추를 붙이며 $event는 key, $item은 항목입니다. open_url은 단독 동작으로 바인딩의 공개 HTTPS 주소를 기본 브라우저로 열고, item_menu에서는 {"item":"필드"}를 씁니다. feed 항목의 media는 {image: MediaRef, kind?: "image"|"video"|"animation", alt?: string} 배열이고 link는 원본 주소입니다. 이 판 미만 쉘에서는 feed의 media와 link가 보이지 않습니다.
table의 동적 columns와 칸 선택은 blocks 24 이상입니다. columns는 열 배열 또는 state, expr, client 등의 바인딩입니다. selection:"cell"에는 selected와 on_select가 필요하며 $event는 {row, column}, $item은 행입니다. row_header는 첫 text 열입니다. content 열의 값은 {title, subtitle?, color?, badges?}이고 max_lines는 본문 1~3줄(기본 3)입니다. 빈 칸도 고를 수 있으며 item_menu는 행 메뉴입니다.
html_view 문서 모음은 문서 이름/r1.html 같은 불변 리비전과 문서 이름/thread.json을 둡니다. thread.json의 comments에서 rev는 처음 단 리비전이고 anchor_rev는 앵커를 만든 리비전입니다. 앵커를 옮기면 anchor_rev를 바꾸고, 없는 값은 rev로 읽습니다. revisions에는 리비전 메타와 사용자가 고친 edits를 둡니다. thread.json은 읽은 revision으로 CAS해 쓰고 충돌하면 최신 값을 읽어 변경을 다시 적용합니다.
11판 sandbox는 asset, file, document, value 가운데 하나의 HTML을 격리된 프레임에서 실행합니다. 자산은 assets에 선언하고 html 형식으로 등록합니다. state_keys와 storage_entries에 적은 항목을 프레임의 window.kaleidoscope 브리지로 읽고 씁니다. slider와 color는 value 상태와 on_change 동작을 받고 input.rows는 여러 줄 입력의 높이를 정합니다.
12판 canvas는 client가 그리는 픽셀 표면이고 timeline은 초 단위 구간과 파형, 마커, 보조 눈금을 그립니다. client는 javascript 자산 entry와 inputs, outputs, actions, commands, state_keys, storage_entries를 선언하며 requires.modules.client를 1 이상으로 둡니다. 창마다 격리된 프레임에서 window.kaleidoscope를 사용합니다. publish로 내보낸 값은 {"client":"이름"}으로 블록에 바인딩하고 이벤트는 {"client":"동작"}으로 처리합니다. input, select, toggle, slider, color의 값과 list, table의 선택은 state 또는 client를 받습니다. client 입력과 코어 명령은 client 출력을 참조하지 않습니다.
onStorageChange(entry, onValue, onError?)는 선언한 저장 항목의 초기 값과 변경을 알립니다. 자동 읽기에 실패하면 onError에 id, code, message가 있는 오류를 전달하며 생략하면 쉘이 창 알림으로 표시합니다. getStorage(entry)는 값을 직접 읽고 실패하면 오류를 돌려주므로 다시 시도에 쓸 수 있습니다.

Windows에서는 실행할 때마다 시스템과 사용자 PATH를 다시 읽으므로, 앱이 설치한 프로그램을 쉘을 다시 켜지 않고 실행할 수 있습니다. 처음 실행하거나 명세가 바뀌면 쉘이 허용을 묻고, 취소하면 {status:"cancelled"}를 돌려줍니다. attach({key})로 같은 창의 실행과 checkpoint에 다시 붙습니다. onReady(listener)는 출력을 읽을 준비가 됐음을 알립니다. read({handle,after,max_bytes})는 바이트를 읽고 ack({handle,after,checkpoint})는 읽은 위치와 상태를 함께 저장합니다. write({handle,bytes,checkpoint})는 입력과 상태를 함께 보내며 close_input({handle})은 입력을 닫고 stop({handle})은 자식 프로세스까지 종료합니다. 한 번에 읽는 출력은 64KiB까지이고 확인되지 않은 출력이 8MiB가 되면 프로그램이 출력을 기다립니다. 실행 권한은 프로그램을 폴더 안에 가두지 않습니다. client.process_permissions와 창 범위 저장소를 선언한 앱은 process.file_uri(blob_key)로 그 창의 저장 파일을 가리키는 file:// 주소를 받습니다. 이 API는 그 창의 저장 파일만 가리키며 임의 경로는 읽을 수 없습니다. file_uri에는 client 4판과 블록 세트 18판이 필요합니다.
블록 세트 18과 client 4를 선언한 앱이 process.start에 services:["tools"]를 주면 현재 연결 서버의 도구 끝점을 services.tools로 돌려줍니다. 연결되지 않았으면 null입니다. stop, 창 삭제, 서버 전환 뒤 주소는 폐기됩니다. onServicesChanged(listener)는 서버 전환을 알리며 attach의 services에서 현재 값을 확인할 수 있습니다. 이 주소를 지원하는 프로그램의 HTTP MCP 설정에 사용합니다.
블록 세트 18과 client 4를 선언하고 client.capabilities에 instructions를 더하면 host.instructions("app_authoring")이 앱 작성 지침 정본과 hash를 돌려줍니다. context_capture를 선언하면 context.prepare({request_id,channel,attachments:{count,bytes}})가 이 창의 작업에서 같이 보는 글, 남은 첨부 한도 안의 그림과 ticket을 돌려줍니다. 그림의 bytes는 Uint8Array입니다. 같은 request_id는 commit 전까지 같은 결과를, commit 뒤에는 빈 글과 그림을 같은 ticket과 함께 돌려줍니다. commit 전에 첨부 수나 크기가 바뀌면 새 request_id를 사용합니다. 같은 창과 채널에 새 request_id를 준비하면 이전 ticket은 쓸 수 없습니다. 돌려받은 글과 그림을 전부 보냈을 때만 context.commit(ticket)을 호출합니다.
값은 리터럴, 상태 참조 {"state":"키"}, 식 {"expr":"JSONata 식"}이며 UI 값에는 클라이언트 출력 참조도 쓸 수 있습니다. 식에서 $state, $data, $storage, $data_meta를 읽고 동작에서는 $event, $item, $modifiers를 읽습니다. $modifiers는 shift, alt, ctrl, meta 참거짓이며 입력되지 않은 경우 모두 false입니다. sources는 파일, 폴더, 연결 요청 또는 공개 HTTPS 원천을 선언합니다. 블록 이벤트에 set_state, refresh, call, set_storage 같은 동작을 연결합니다. actions라는 최상위 필드는 없습니다.
원천을 넣기 전에 호출 수를 셉니다. 호스트마다 기본 화면의 분당 호출이 6회를 넘지 않게 합니다. upload_app과 preview_app이 넘은 호스트를 warnings로 알립니다. refresh_secs는 자료가 실제로 바뀌는 주기보다 짧게 두지 않고, 일간이나 연간 자료에는 두지 않습니다. 코인이나 도시처럼 항목마다 부르는 원천은 묶음 요청을 먼저 찾습니다. 시세처럼 자주 바뀌는 값을 다른 원천의 쿼리에 넣지 않습니다. 값이 바뀔 때마다 그 원천을 다시 부르기 때문입니다. 코어는 보이지 않는 창, 안 보는 탭, 접힌 섹션에서만 쓰는 원천을 부르지 않고, 다시 보일 때 기한이 지난 것만 받습니다. 429와 Retry-After는 호스트 단위로 지키며 마지막 값을 유지합니다. 탭 안에서만 쓰는 값은 그 탭의 블록만 읽습니다. 다른 블록이 읽거나 식이 $data 전체를 읽으면 그 원천은 쉬지 못합니다. 워커가 외부를 부를 때는 429를 받으면 그 주기를 끝내고 Retry-After까지 부르지 않습니다.

목록은 무한 스크롤이 기본입니다. 항목을 늘어놓는 원천의 상류가 쪽 넘김(커서, 쪽 번호, offset)을 주면 request 원천에 page를 선언하고, limit 같은 개수 키로 목록을 잘라 끝내지 않습니다. page는 {"param":"cursor","next":"nextCursor","items":"items"}처럼 다음 쪽 요청 query에 넣을 키(param), 응답 하나를 뿌리로 다음 쪽 값을 내는 JSONata 식(next), 응답에서 항목 배열의 자리(items, 점으로 이은 키 경로이고 생략하면 응답 자체가 배열)를 받습니다. next가 문자열이나 숫자면 다음 쪽이 있고 null, false, 빈 값이면 끝입니다. next 식에서 $loaded는 지금까지 이어 붙인 항목 수, $pages는 받은 쪽 수입니다. 코어가 다음 쪽을 items 자리에 이어 붙이므로 $data.이름은 첫 응답 모양 그대로이고, 그 원천을 읽는 list, table, feed(follow 제외)와 세로나 격자의 virtual repeat은 끝에 가까워지면 스스로 다음 쪽을 받습니다. 검색어처럼 query가 바뀌면 첫 쪽부터 다시 받고, refresh 동작은 받은 쪽 수만큼 다시 받으며, 쪽을 둘 이상 받은 원천은 refresh_secs 자동 다시 받기를 쉽니다. 다음 쪽은 사용자가 끝까지 내렸을 때만 부르므로 호출 예산에 넣지 않습니다. feed.follow처럼 꼬리를 따라가는 목록과 [0..9]처럼 잘라 보이는 요약에는 쪽 넘김 원천을 쓰지 않습니다. 상류가 쪽을 주지 않으면 한 번에 받을 수 있는 최대 개수로 받습니다. page를 쓰면 requires.blocks는 22 이상이어야 합니다.
권한 id에는 소문자, 숫자와 하이픈을 쓰며 profiler 권한은 밑줄도 쓸 수 있습니다. profiler 모듈 1판의 권한 {"module":"profiler","id":"이름","label":"설명"}은 이 기기 코어의 성능 통계를 제공합니다. request 원천으로 GET /snapshot을 읽고 call로 POST /clear 또는 POST /benchmark를 실행합니다. 서버 미리 보기에서는 data 표본이 필요합니다.
storage.entries는 JSON 또는 Markdown 항목의 키, 스키마, 기본값을 선언합니다. 문서 모음은 collection:true인 숨김 Markdown 항목이며 기본값은 빈 문자열이고 key 아래에 문서별 행을 둡니다. 모음 문서는 list_app_storage(entry_id), read_app_storage(entry_id, doc), write_app_storage(entry_id, doc), reset_app_storage(entry_id, doc), move_app_storage로 다룹니다. 각 문서는 1MiB 한도와 revision CAS를 따릅니다. 작업별 키에는 {workspace_id}를 씁니다. 고정 항목에는 doc을 쓰지 않습니다. worker는 앱의 서버 실행과 주기 작업을 선언하며 시크릿 값은 앱 정의에 넣지 않습니다. opens는 파일 확장자, 폴더 권한과 경로 상태 키를 선언합니다.

파일 권한은 files 1판에서 폴더 안 항목을 나열하고 읽고 씁니다. files 2판의 pc 범위는 읽기 전용입니다. files 3판은 readwrite + folder 권한에서 폴더 생성, 이름 변경, 이동, 복사와 삭제를 할 수 있습니다. 삭제는 기본적으로 시스템 휴지통을 사용하며, 휴지통을 사용할 수 없으면 오류로 끝납니다. 영구 삭제는 별도 요청입니다. 이름이 겹치면 덮어쓰지 않으며 복사만 자동으로 「- 복사본」 이름을 붙입니다. files.reveal과 files.path는 읽기 권한으로 쓸 수 있습니다.
worker.webhook은 외부 POST 트리거를 선언합니다. enabled_entry는 기본값이 false인 전역 불리언 저장 항목이며, token_secret은 반드시 지정해야 하며 미리 시크릿을 설정해야 호출할 수 있습니다. 응답을 http_response로 정하고 defer로 선언된 동작을 뒤에 실행할 수 있습니다. worker.calls에 다른 앱 id를 선언하면 파이썬에서 kaleidoscope_worker.call_app과 read_app_storage를 사용할 수 있습니다. 자기 호출, 순환 호출과 네 단계 초과 호출은 거부됩니다.

앱 정의의 settings와 window_title은 블록 세트 19판이 필요합니다. settings.ui는 앱 설정 패널의 블록 트리이며, 있으면 storage.entries의 presentation:settings 자동 폼 대신 이 트리를 표시합니다. settings.available은 선택 바인딩이고 생략하면 설정 버튼이 보이며, false면 버튼을 숨기고 열린 설정을 닫습니다. window_title.title은 창 제목 바인딩이고 meta는 제목 옆에 표시할 선택 바인딩입니다. 바인딩 포인터는 /settings/available, /settings/ui 아래, /window_title/title과 /window_title/meta입니다.

button.description은 올림 또는 키보드 초점에 보이는 설명 바인딩입니다. icon_only의 label도 쉘 도움말로 보입니다. description을 쓰면 requires.blocks를 28 이상으로 선언합니다.
32판부터 button.variant는 default, primary, danger, ghost, chip 리터럴 또는 그 이름을 내는 바인딩을 받습니다. 알 수 없는 바인딩 값은 default로 표시합니다. 아이콘 film, sticker, image-play도 32판부터 쓸 수 있습니다. 이를 쓰면 requires.blocks를 32 이상으로 선언합니다.

메시지 수신 계약: client.capabilities에 receive_message를 선언하는 앱은 requires.blocks 29와 requires.modules.client 6 이상을 지정합니다. 클라이언트의 onMessage(handler)로 {request_id, text}를 받으며 {status:"accepted"}는 접수 완료이지 답변 완료가 아닙니다. 준비되지 않았으면 {status:"not_ready", reason}을 돌려주고 reason에는 사용자가 할 일을 적습니다. agent 제공자와 receive_message가 둘 다 있으면 대화 제공자 경로를 우선합니다. 초기 코드에서 window.kaleidoscope.onMessage(async (message) => ({ status: "accepted" }))를 한 번 등록합니다. handler는 오래 걸리는 답변 생성을 기다리지 말고 5초 안에 접수 결과를 반환하세요.
text/search input에 options 바인딩을 두면 글로 거르는 선택지가 뜹니다. 문자열 또는 {value:문자열,label:문자열,description?:문자열} 배열입니다. options_only:true면 목록 값만 확정하며 여러 줄 입력과 함께 쓰지 않습니다. select는 짧은 목록에서 JSON 값을 고르는 별도 단추이고 선택지 description은 select 메뉴에도 보입니다. 이 필드를 쓰면 requires.blocks를 33 이상으로 선언합니다.

input.kind=date는 YYYY-MM-DD, time은 HH:mm 문자열을 쓰며 빈 값은 null입니다. min과 max도 같은 ISO 형식 바인딩입니다. 표시는 앱 locale을 따르고 직접 ISO 입력도 됩니다. time.step은 분 단위 목록 간격이며 기본은 30분입니다. date에는 step이 없습니다. 이 종류를 쓰면 requires.blocks를 35 이상으로 선언합니다.
